# Review notes — not part of the published site

Deliberately kept out of `docs/` so `mkdocs` never builds or serves it. This is a private note to Sharmilan, not audience-facing.

Two kinds of things below: (1) things I noticed in the **app repo** (`sutra`, read-only — nothing there was touched) that are worth your own attention, independent of this docs task, and (2) judgment calls I made while writing this site that you should sanity-check.

## Things worth a look in the app repo (not touched, just observed)

1. **Release workflow tag-trigger looks mismatched.** `backend-release.yml` and `frontend-release.yml` both gate on `startsWith(github.event.release.tag_name, 'v')`, but every doc (`infrastructure/gcp/README.md`, the app's own `docs/deployment.md`) describes the actual tag scheme as `backend-vX.Y.Z` / `frontend-vX.Y.Z` — which doesn't start with `v`, it starts with `b` or `f`. As written, either both workflows fire off a bare `vX.Y.Z` tag (not the documented one), or neither fires off the documented prefixed tag — worth confirming what actually happens on your next release, since it's cheap to get wrong quietly.

2. **`infrastructure/aws/README.md` says "Local state... no remote backend configured yet," but it's stale.** Both `infrastructure/aws/terraform/versions.tf` and `infrastructure/gcp/terraform/versions.tf` declare a `cloud { organization = "sutras", workspaces { name = "aws"/"gcp" } }` backend — i.e. Terraform Cloud, not local state. I wrote the public docs to reflect the `versions.tf` reality (remote state), not the README's claim, since the code is more authoritative than the prose next to it. Worth updating that README line so it doesn't mislead the next reader (including future you).

3. **Production Redis has zero persistence.** `infrastructure/gcp/helm/sutras/templates/redis-deployment.yaml` mounts no volume at all — confirmed by reading the template, not inferred. Every pod reschedule (which your own node-autoscaler comment in `gke.tf` says will happen routinely at min_node_count=1) silently drops the cache *and* any unacked pipeline job in the Messenger stream. I surfaced this prominently across Architecture/Decisions/Scaling/Roadmap on the public site since it's the single most concrete reliability gap I found — flagging here too in case it's more urgent to you than the roadmap ordering implies.

4. **AWS RDS has no explicit `backup_retention_period` in `rds.tf`.** Not necessarily broken (AWS has a default), but worth setting explicitly and confirming rather than relying on whatever the provider default happens to be — especially since UAT carries real test data per your own `aws/README.md`.

5. **`aws_ecs_cluster_capacity_providers.main` registers `FARGATE_SPOT` but the `default_capacity_provider_strategy` only uses `FARGATE`** (weight 1, no Spot in the mix). Since UAT is non-critical and already run only in short bursts, adding Spot to the default strategy (or splitting weight between the two) could shave a further chunk off the ~$130/mo "if left running" estimate at basically no risk — flagged as a possible cheap win, not written into the public roadmap since it's a small optimization, not a gap.

6. **No PodDisruptionBudget or HorizontalPodAutoscaler anywhere in the Helm chart.** You clearly know this — `gke.tf`'s own comments discuss the tradeoff explicitly — so this is more a "confirmed, not news to you" than a discovery. Public roadmap reflects it under Next/Later per your own framing.
